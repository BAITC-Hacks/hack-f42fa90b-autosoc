# Требования к сервису

## Назначение и границы этапа

Сервис помогает подобрать подрядчиков или площадки для мероприятия. На текущем этапе зафиксированы требования; подбор ещё не реализован. Регистрация, бронирование, оплата и ведение собственной базы данных не входят в объём задачи.

## Входные параметры

Обязательные параметры запроса:

- город;
- дата мероприятия;
- формат мероприятия;
- категория подрядчика или площадки;
- бюджет в тенге.

Необязательные параметры:

- предпочтительный язык;
- требуемое количество часов.

Ввод должен валидироваться до запуска подбора. Семантика `max_hours = null` в профиле означает, что работа не привязана к количеству часов, а не нулевую доступность.

## Результат

Сервис возвращает не более трёх карточек. Каждая карточка содержит данные профиля и конкретное объяснение выбора в 1–2 предложениях, основанное только на проверенных фактах: соответствии городу, категории, формату, бюджету, языку, часам и доступности.

Цена с пометкой «от» является ориентиром и не считается окончательной сметой. Интерфейс должен явно сообщать об этом пользователю.

Порядок результатов детерминирован: одинаковые входные данные и один набор профилей дают один порядок. Критерии ранжирования и стабильный критерий разрешения равенства должны быть явно реализованы и покрыты тестами.

Если найдено только один или два подходящих профиля, сервис возвращает их и объясняет, почему не удалось заполнить все три позиции (например, остальные профили заняты или не прошли заданные ограничения).

## Доступность

- Профили, занятые на выбранную дату, исключаются из результата. Правило распространяется и на площадки.
- Календарь достоверно покрывает период с **23.09.2026 по 31.12.2026 включительно**.
- Для дат вне этого периода доступность считается неизвестной. Сервис не должен представлять её как подтверждённую; это состояние должно быть явно отражено в ответе.

## Исходы подбора

Сервис различает три исхода:

1. **Подобрали** — найден хотя бы один профиль, удовлетворяющий ограничениям.
2. **Категории нет в городе** — в исходных данных нет профилей запрошенной категории для выбранного города.
3. **Категория есть, но все отсеяны** — профили категории в городе существуют, однако каждый исключён из-за даты, бюджета или других заданных ограничений. Ответ должен кратко указывать фактические причины отсева.

Пустой результат нельзя маскировать вымышленными рекомендациями.

## Происхождение данных

Для каждого профиля необходимо сохранять и передавать без домыслов:

- `synthetic` — является ли профиль синтетическим;
- `city_imputed` — был ли город восстановлен или дополнен;
- `price_imputed` — была ли цена восстановлена или дополнена;
- происхождение профиля (источник или предусмотренный датасетом идентификатор происхождения).

Исходный датасет нельзя изменять. На момент подготовки требований файл `data/hackathon-dataset-anonymized.jsonl` отсутствует; отсутствие не подменяется вымышленными данными и не мешает завершению документального этапа.

## Демонстрационные сценарии

После реализации должны быть воспроизводимо показаны:

1. плотная категория с несколькими подходящими кандидатами;
2. редкая категория с одним или двумя кандидатами и объяснением нехватки;
3. пустой результат с корректным различением причины;
4. смена даты, которая изменяет выдачу именно из-за занятости.

Ориентир времени ответа сервиса — до 10 секунд.

## Организационные ограничения и критерий готовности

- Фактический прогресс фиксируется за каждый час; запланированное не отмечается как выполненное.
- Основная работа выполняется только в выданном командном репозитории.
- Финальная версия должна быть готова **23.09.2026 к 18:00 по времени Астаны**.
- Чистый запуск по README должен работать без личного аккаунта участника.
- Наличие документов с требованиями и архитектурой само по себе не означает прохождение проверки организаторов.
