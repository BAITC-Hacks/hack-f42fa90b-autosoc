# Архитектура

## Статус

Backend и статический сайт из описанной архитектуры реализованы. Интеграция AI остаётся планом.

## Компоненты

Приложение построено на Python и FastAPI. Тот же сервер отдаёт статический сайт на HTML, CSS и JavaScript без сборщика и отдельного frontend-сервера.

Backend разделяется на модули с одной ответственностью:

- `data` — чтение исходного CSV в UTF-8-SIG через `csv.DictReader` без его изменения, проверка схемы и доступ к профилям;
- `schemas` — схемы запросов, ответов и профилей, включая признаки происхождения данных;
- `matcher` — детерминированная фильтрация, различение пустых исходов и ранжирование;
- `explain` — построение кратких шаблонных объяснений исключительно из фактов, подтверждённых результатом фильтрации.

Код проверяет ограничения, исключает занятых и ранжирует кандидатов. В реализованном этапе используются только шаблонные объяснения; AI API не вызывается. Возможное будущее подключение AI не должно менять фильтры и порядок.

## Реализованный HTTP API

Сайт доступен по `GET /`; каталог `static/` отдаётся по `/static/`. JavaScript получает значения формы из `GET /api/options` и отправляет запросы в `POST /api/match`, не повторяя правила подбора.

### `GET /health`

Проверка готовности процесса обслуживать запросы. Не должна раскрывать конфигурацию или секреты.

### `GET /api/options`

Возвращает доступные значения для формы (например, города, форматы и категории), полученные из фактически загруженных данных.

### `POST /api/match`

Принимает параметры подбора, валидирует их и возвращает один из трёх исходов, до трёх упорядоченных карточек, объяснения, сведения о неполной выдаче и статус известности доступности.

Точные JSON-схемы заданы в `app/schemas.py`; проверка входа и отрицательные сценарии покрыты тестами.

## Поток запроса

1. `schemas` валидирует входные параметры.
2. `data` предоставляет неизменённые исходные сведения и нормализованное представление.
3. `matcher` устанавливает наличие категории в городе, применяет ограничения и формирует детерминированный рейтинг.
4. `explain` получает только подтверждённые факты и создаёт шаблонные объяснения.
5. API возвращает структурированный ответ статическому сайту или другому HTTP-клиенту.

## Хранение и безопасность

На первом этапе не добавляются база данных, регистрация и бронирование. Исходный датасет остаётся неизменным. Секреты передаются через окружение и не сохраняются в Git; пример конфигурации при необходимости должен содержать только безопасные заглушки.

Архитектура должна обеспечивать чистый запуск по README без личного аккаунта участника. Сторонние компоненты и их назначение необходимо раскрывать в документации по мере фактического добавления.
