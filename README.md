# Умный подбор подрядчиков

Сервис для подбора подрядчиков и площадок под параметры мероприятия в рамках задачи HackAlem AI «Умный подбор подрядчиков» (#79-lite). Пользователь задаёт город, дату, формат, категорию и бюджет, а сервис должен вернуть до трёх подходящих вариантов с краткими, проверяемыми объяснениями.

## Текущий статус

Реализованы backend и статический сайт: загрузка локального CSV, детерминированный подбор, проверяемые объяснения, HTTP API и форма с результатами. AI может выбрать фрагмент описания для уже подобранных профилей; без ключа сайт и API работают в шаблонном режиме. Наличие кода и документов само по себе не означает прохождение проверки организаторов.

Для запуска нужен предоставленный организаторами `hackathon dataset anonymized.csv` в `data/` (предпочтительно) или в корне проекта. Файл локальный, **в Git не входит** и приложением не изменяется. Без него запуск завершается явной ошибкой. Дополнительный `data/synthetic_extra.csv` загружается только при наличии и должен иметь ту же схему; его происхождение в API отличается от исходных профилей. В этом этапе дополнительных профилей не создано.

## Стек и зависимости

- Python 3.11+ и стандартный модуль `csv` — чтение CSV в UTF-8-SIG;
- FastAPI (MIT) — HTTP API; Pydantic (MIT) — контракты и валидация;
- Uvicorn (BSD-3-Clause) — локальный сервер;
- pytest (MIT) — тесты; httpx (BSD-3-Clause) — клиент API в тестах;
- официальный OpenAI Python SDK (Apache-2.0) — один необязательный запрос к Responses API для выбора цитат; python-dotenv (BSD-3-Clause) — чтение локального `.env`;
- HTML, CSS и JavaScript без сторонних библиотек и сборщика — сайт на том же сервере.

Версии зафиксированы в `requirements.txt`. База данных и личный аккаунт для запуска не нужны. Без OpenAI API основной подбор и объяснения остаются доступными.

## Установка и запуск в PowerShell

Из корня репозитория при установленном Python 3.11+:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Проверки запускаются без активации окружения:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

После запуска `GET http://127.0.0.1:8000/health` возвращает состояние и число загруженных профилей.

Откройте **http://127.0.0.1:8000/** в браузере. FastAPI отдаёт страницу по `/`, CSS и JavaScript по `/static/`. Форма загружает варианты из `/api/options` и отправляет подбор в `/api/match`; четыре демонстрационные кнопки заполняют форму и выполняют настоящие запросы по сценариям ниже. Предыдущие результаты убираются во время нового запроса. Сайт показывает ошибки сети и валидации, до трёх карточек, проверяемые факты и причины отсева.

Пример прямого запроса к API:

```powershell
$body = @{ city='Алматы'; date='2026-10-07'; event_format='свадьба'; category='Ведущий'; budget_kzt=1000000 } | ConvertTo-Json
Invoke-RestMethod -Uri 'http://127.0.0.1:8000/api/match' -Method Post -ContentType 'application/json; charset=utf-8' -Body $body
```

`GET /api/options` возвращает города, категории по городам, форматы, языки и границы календаря. `POST /api/match` принимает также необязательные `language` и `hours` и возвращает `matched`, `no_category_in_city` или `all_filtered`, максимум три карточки и число всех прошедших профилей. Для каждого отсеянного кандидата ответ содержит `all_reasons` с конкретными значениями и отдельно `primary_reason` с `detail`. Все причины одного профиля могут пересекаться; `primary_reason_counts` учитывает профиль только один раз. Порядок основных причин: дата, формат, бюджет, язык, часы, недостаток данных. Запрос с датой за пределами **2026-09-23 — 2026-12-31** возвращает 422: занятость вне окна неизвестна.

## Режим объяснений и локальные настройки

По умолчанию `EXPLANATION_MODE=auto`: если `OPENAI_API_KEY` доступен в окружении или локальном `.env`, официальный SDK делает один запрос Responses API для всех показанных карточек. Модель `OPENAI_MODEL` настраивается; в `.env.example` указана `gpt-4o-mini`. Для работы без внешних вызовов задайте `EXPLANATION_MODE=template`. Переменные процесса имеют приоритет над `.env`; файл `.env` игнорируется Git. Пример локальной настройки:

```powershell
Copy-Item .env.example .env
# Отредактируйте .env локально; задайте OPENAI_API_KEY только при желании использовать AI.
```

Ключ нельзя передавать в браузер или сохранять в Git. Модель получает только параметры заказа, проверенные факты и описания максимум трёх уже выбранных профилей. Она выбирает точный фрагмент собственного описания каждого профиля; кандидатов и порядок определяет только код. Код проверяет id, отсутствие дубликатов, принадлежность цитаты конкретному описанию и длину. Соответствие JSON-схеме само по себе не подтверждает правдивость текста. Финальные 1–2 предложения собирает код, атрибутируя особенности как слова из описания профиля. При отсутствии ключа, таймауте, отказе, ошибке или недостоверной цитате применяется шаблон с проверенным фрагментом либо честным указанием на нехватку сведений. В карточке указано происхождение объяснения и показана цитата. Весь AI-этап ограничен примерно 7 секундами, автоматические повторы SDK отключены.

Использован синтаксис Structured Outputs из [официальной документации OpenAI](https://developers.openai.com/api/docs/guides/structured-outputs). Работа без ключа и отказные сценарии проверяются с подменённым клиентом; это не является проверкой реального OpenAI API.

Карточки сортируются по цене «от» по возрастанию, при равенстве по `id`. Показатель `rank_score` равен доле запаса бюджета `(budget_kzt - price_from_kzt) / budget_kzt`; он отражает только ценовое соответствие, не качество подрядчика. Цена «от» не является окончательной сметой. `max_hours=null` означает отсутствие привязки к часам в каталоге, а не неограниченное время обслуживания.

## Проверенные данные и сценарии

В локальном исходном CSV проверены 66 строк: Алматы — 50, Астана — 15, Зарубежье — 1. Уникальных категорий 17; чаще всего встречаются «Ведущий» (15 профилей), «Фотограф» (12), «Банкетный зал» (8) и «Ресторан» (7). Категории одного профиля могут учитываться в нескольких группах. Пустых `max_hours` — 9; пустых цен, форматов и языков — 0. `synthetic=True` — 13, `city_imputed=True` — 8, `price_imputed=True` — 18. Это признаки исходного файла; новых записей здесь нет.

Воспроизводимые запросы (`city`, `date`, `event_format`, `category`, `budget_kzt`):

| Сценарий | Параметры | Фактический исход |
| --- | --- | --- |
| Плотная категория | Алматы, 2026-10-07, свадьба, Ведущий, 1000000 | `matched`, 5 прошли, 3 карточки, 1 исключён датой |
| Редкая категория | Астана, 2026-09-23, свадьба, Флорист, 300000 | `matched`, 1 профиль |
| Нет совпадений | Алматы, 2026-10-10, свадьба, Ведущий, 300000 | `all_filtered`, 0 профилей |

| Влияние календаря | Алматы, 2026-10-10, свадьба, Ведущий, 1000000 | `matched`, 2 прошли, 4 исключены датой; остальные параметры совпадают с первым запросом |

6. Реализовать API и минимальный статический интерфейс — сделано.
7. Покрыть ключевые сценарии тестами и проверить локальный запуск — сделано.
8. Подготовить и проверить демонстрационные сценарии — сделано по локальному CSV.

При чистом запуске требуется только локальная копия предоставленного CSV, Python и установка зависимостей; личный аккаунт участника не нужен. **Открытый вопрос финальной воспроизводимости:** исходный CSV пока находится только локально и не входит в Git, поэтому для чистого клона организаторы должны предоставить этот файл отдельно.
